# HttpEvolution

Компактне C#-демо еволюції HTTP: одна можливість на коміт.
**Зараз реалізовано тільки перший крок — HTTP/0.9 (1991).**
Мережа: `TcpListener` → `TcpClient` → потік байтів; без ASP.NET, Kestrel,
`HttpListener`, `HttpClient` і сторонніх пакетів.

## Запуск

Потрібен .NET 10 SDK. У папці репозиторію:

```sh
dotnet run
```

В іншому терміналі (Linux/macOS, потрібен `nc`):

```sh
printf 'GET /\r\n' | nc 127.0.0.1 8080
# <h1>Hello, HTTP/0.9!</h1>

printf 'GET /missing\r\n' | nc 127.0.0.1 8080
# <h1>Not found</h1>
```

Альтернатива: `curl --http0.9 http://127.0.0.1:8080/`.
Цей прапорець дозволяє відповідь 0.9; curl надсилає сучасний рядок запиту,
а сервер ігнорує слова після адреси, як дозволяє первинний опис 0.9.
Для точного запиту 0.9 використай `nc`. Для показу цього кроку браузер не потрібен.

## Що видно на дроті

Запит: ASCII-рядок `GET /\r\n` (також приймається LF).
Відповідь: лише HTML; немає версії, статусу чи заголовків.
Після відповіді сервер закриває з'єднання — це і є її кінець.
Єдина сторінка — `/`; інші адреси отримують HTML про відсутність сторінки,
без коду 404. Невідомі методи й порожні запити закриваються без відповіді.

Для стислості: один клієнт за раз, тільки loopback:8080, таймаут читання/запису
5 секунд, без обмеження довжини рядка. Це локальна демонстрація протоколу.

## Наступні кроки (ще не реалізовані)

Дати показують історичну появу або публікацію специфікацій, а не версії .NET.
Кожен пункт із кількома можливостями розбивається на окремі короткі коміти.

| Період | Що додати |
| --- | --- |
| 1991 — HTTP/0.9 | **Готово:** GET → HTML → закриття TCP |
| 1995–1996 — HTTPS/SSL | Пояснити появу захищеного HTTP; SSL залишити історичним контекстом |
| 1996 — HTTP/1.0 | Версія і статус; заголовки; Content-Length; HEAD — окремими комітами |
| 1997 — HTTP/1.1 | Host; keep-alive; chunked encoding — окремими комітами |
| 1999 — TLS 1.0 | Показати заміну SSL на TLS; сучасне HTTPS додати через TLS-потік |
| 2015 — HTTP/2 | Бінарні кадри; SETTINGS; HPACK; кілька потоків — окремими комітами |
| 2018 — TLS 1.3 | Показати сучасне TLS-узгодження |
| 2022 — HTTP/3 | QUIC поверх UDP з TLS 1.3; потоки; кадри; QPACK |

HTTPS — HTTP усередині захищеного каналу, а не окрема версія HTTP.
Перед реалізацією захищених етапів потрібно визначити межі початкового обмеження:
`SslStream` дає TLS поверх `TcpClient`, але виходить за перелік дозволених класів.
SSL та старі TLS описуємо історично; для виконуваного демо використовуватимемо сучасний TLS.
Сам `UdpClient` дає лише дейтаграми: HTTP/3 потребує ще QUIC, TLS і QPACK.
Власна реалізація цих шарів суттєво збільшить код; готовий QUIC теж розширить
перелік дозволених API. Звичайний обмін текстом через UDP не є HTTP/3.
